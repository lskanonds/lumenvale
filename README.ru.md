Корпоративный сайт и система управления контентом для **Lumenvale Energy**, компании, которая
обслуживает солнечные электростанции и накопители энергии для их владельцев. Публичная часть
написана на Next.js, а сотрудники компании редактируют всё содержимое в админке Payload CMS,
встроенной в то же приложение: станции, услуги, команду, вакансии, целые страницы, контакты и
юридические тексты.

> **Демо-проект.** Lumenvale Energy — вымышленная компания. Её станции, сотрудники, цифры и
> контакты придуманы, все почтовые адреса используют зарезервированный домен `.example`. Код при
> этом настоящий: законченный сайт с удобной для редакторов CMS, готовый к развёртыванию.

## Возможности

- **Одно приложение, два слоя.** Статически сгенерированный сайт на Next.js и админка Payload по
  адресу `/admin` развёрнуты вместе. После публикации в админке нужные страницы обновляются за
  несколько секунд через `revalidatePath`, без пересборки.
- **Конструктор страниц с ограничителями.** Редакторы собирают страницы из 14 блоков. Каждый блок
  выбирает фон из фиксированного списка _поверхностей_, а поверхность сама задаёт цвет текста,
  поэтому никакая комбинация в админке не нарушит контраст и не выйдет за палитру бренда.
- **Живой предпросмотр.** Черновики сохраняются автоматически, а настоящая страница
  перерисовывается рядом с формой в ширине телефона, планшета или десктопа. Перетаскиваемый
  разделитель заменяет жёсткое деление Payload 40/60.
- **Кейсы, которые начинаются с цифр.** Страница каждой станции открывается показателями:
  карточки метрик, строка происхождения данных (период, источник, размер группы сравнения) и
  месячный график индекса выработки на чистом SVG с той же информацией в доступной таблице.
- **Формы, которые не теряют заявки.** Заявки проходят через server actions с валидацией и
  honeypot-полем, а после отклонённой отправки ответы посетителя восстанавливаются. Запись
  сохраняется до отправки письма-уведомления, поэтому сбой почты стоит письма, а не заявки.
  Необязательные вложения уходят письмом и нигде не хранятся.
- **Админка для не-разработчиков.** Брендированный вход, памятка на главной панели, подписи полей
  обычным языком, схематичные миниатюры блоков, автоматическая уборка брошенных черновиков, и
  первый созданный аккаунт всегда получает права администратора.
- **Безопасный запуск.** `robots.txt` и мета-тег robots управляются одним переключателем
  `ALLOW_INDEXING` и по умолчанию закрыты; `PREVIEW_MODE` прячет админку и API на превью-деплоях.
- **Доступность.** Сделано под WCAG 2.1 AA и проверено axe-core на десктопе и телефоне: полная
  работа с клавиатуры, видимый фокус, учёт `prefers-reduced-motion`.

## Запуск

Нужны Node.js 20.9 или новее и Docker.

```bash
docker compose up -d     # PostgreSQL на localhost:5434
cp .env.example .env     # затем задайте PAYLOAD_SECRET, например: openssl rand -hex 24
npm install
npm run dev
```

Во втором терминале загрузите демо-контент:

```bash
npm run seed
```

После этого откройте:

- сайт: http://localhost:3000
- админку: http://localhost:3000/admin. Первый созданный там аккаунт всегда администратор; можно
  создать его и из терминала: `npm run seed:user -- you@example.com 'надёжный-пароль'`
- страницу бренда: http://localhost:3000/brand-kit (только в режиме разработки)

В режиме разработки Payload сам применяет схему к базе данных. В продакшене вместо этого
применяются миграции из `src/migrations` (`npm run migrate`), поэтому используйте для этих режимов
разные базы.

## Архитектура

**Слой чтения.** Компоненты не работают с документами Payload напрямую: `src/lib/cms.ts`
преобразует их в типы из `src/lib/types.ts`, поэтому изменения схемы гасятся в одном месте.
Исключение одно: секции страниц сразу попадают в рендереры блоков в `src/blocks/Sections.tsx`.
Каждое чтение обёрнуто в `cache` из React, так что несколько компонентов, запрашивающих настройки
сайта, делают один запрос.

**Черновики и предпросмотр.** Панель предпросмотра и кнопка «View on site» проходят через
`/next/preview`: маршрут проверяет сессию админки и включает draft mode в Next.js. После этого
слой чтения отдаёт черновики вместо опубликованных документов, и ни одной странице не нужно
знать о существовании предпросмотра.

**Ревалидация.** Хуки в `src/hooks/revalidate.ts` сбрасывают кэш страницы документа, списков, в
которых он показан, и всего layout, когда изменение затрагивает каждую страницу (настройки сайта
или страница, добавленная в меню). Автосохранения пропускаются, чтобы набор текста не сбрасывал
кэш.

**Поверхности и токены.** `src/lib/surfaces.ts` связывает каждый фон с подходящим к нему цветом
текста. Цвета в `src/app/(frontend)/styles.css` названы по роли (`primary`, `accent`), поэтому
смена фирменного стиля сводится к замене значений, а не к поиску и замене по коду.

**Формы.** `src/actions/enquiry.ts` проверяет данные, отсекает ботов honeypot-полем, сохраняет
заявку и только потом отправляет уведомление. Правила для вложений лежат в
`src/lib/attachments.ts` в виде чистых функций: белый список, проверяемый и по расширению, и по
типу файла, лимит общего размера и пересборка имени файла, чтобы за ним нельзя было спрятать
другое расширение.

**Поисковики.** `ALLOW_INDEXING=1` открывает сайт и в `robots.txt`, и в мета-теге robots; всё
остальное (превью-деплои, локальные машины, копии базы) по умолчанию закрыто. Карта сайта
содержит маршруты из кода и все опубликованные страницы, станции и услуги.

## Тесты

| Команда                                 | Что проверяет                                                         |
| --------------------------------------- | --------------------------------------------------------------------- |
| `npm run typecheck`, `npm run lint`     | TypeScript в строгом режиме и ESLint                                  |
| `npm run test:int`                      | Правила вложений (белый список, лимит размера, опасные имена файлов) и smoke-тест API Payload |
| `npm run test:e2e`                      | Навигацию, шапку и мобильное меню, правила кейса (нет пустых метрик, есть происхождение данных, график и таблица совпадают), сохранение ответов формы после отклонённого файла, страницу 404, главную, список и редактирование в админке |
| `node scripts/a11y.mjs / /portfolio`    | Аудит axe-core по WCAG 2.1 AA на ширине 1440 и 390 px; при любом нарушении завершается с ошибкой |
| `node scripts/shots.mjs / .shots`       | Скриншоты всех секций на десктопе и телефоне                          |

Интеграционным и e2e-тестам нужна запущенная база с демо-контентом. Playwright сам поднимает
сервер разработки, если порт 3000 свободен. Оба скрипта из `scripts/` принимают `SHOT_BASE_URL`,
чтобы проверять продакшен-сборку или превью-деплой.

## Развёртывание

Проект рассчитан на Vercel с управляемой базой Postgres; `vercel.json` применяет миграции перед
каждой сборкой. Что нужно развёртыванию сверх локальной разработки:

| Переменная                      | Назначение                                                        |
| ------------------------------- | ----------------------------------------------------------------- |
| `DATABASE_URL`                  | Управляемый Postgres (Neon, Supabase, RDS и т. п.)                |
| `PAYLOAD_SECRET`                | Подписывает сессии админки; `openssl rand -hex 24`                |
| `NEXT_PUBLIC_SITE_URL`          | Адрес, по которому сайт реально доступен; из него строятся ссылки сброса пароля |
| `BLOB_READ_WRITE_TOKEN`         | Хранилище Vercel Blob для загрузок; подставляется при подключении хранилища |
| `RESEND_API_KEY`, `EMAIL_FROM`  | Письма сброса пароля и уведомления о заявках                      |
| `ALLOW_INDEXING`                | `1` только на боевом продакшен-деплое                             |
| `PREVIEW_MODE`                  | `1` на превью-деплоях; прячет `/admin` и `/api`                   |

Без `RESEND_API_KEY` Payload пишет письма в лог вместо отправки и всё равно сообщает об успехе,
поэтому задайте ключ до того, как кто-то начнёт полагаться на сброс пароля или уведомления о
заявках.

## Структура проекта

```
src/
  app/(frontend)/      публичный сайт, по каталогу на маршрут
  app/(payload)/       админка Payload и REST/GraphQL-эндпоинты
  actions/             server actions (формы заявок)
  blocks/              блоки конструктора: конфигурация и рендереры
  collections/         коллекции Payload
  globals/             настройки сайта и главная страница
  components/          знаки бренда, layout, секции главной, кейс, интерфейс админки
  hooks/               URL предпросмотра, автосохранение, ревалидация, уборка черновиков
  lib/                 слой чтения CMS, доменные типы, поверхности, правила вложений
  seed/                демо-контент
  migrations/          миграции базы данных
public/blocks/         схематичные миниатюры для выбора блоков
scripts/               аудит доступности и скриншоты
tests/                 наборы тестов Vitest и Playwright
```
